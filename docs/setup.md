# Setup

## Requirements

- Node.js 20.9 or newer
- npm
- Docker Desktop for local Supabase
- A Supabase project for hosted development

## Application

1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env.local`
3. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
4. Run `npm run dev`

## Supabase local development

1. Start Docker.
2. Run `npm run supabase:start`
3. Apply migrations with `npm run supabase:reset`
4. Copy the local API URL and publishable key into `.env.local`

Useful commands:

- `npm run supabase:status`
- `npm run supabase:reset`
- `npm run supabase:stop`

## Assigning an admin

Admin roles are stored only in Supabase Auth `app_metadata.role`. Registration and client requests must never assign or change roles.

### Local Supabase

1. Register or create the intended account through `/register`, Studio, or the Supabase Auth API.
2. Run:

```powershell
npm run admin:set -- -Email user@example.com -Role admin
```

Use `-Role student` to demote an account. The script updates `auth.users.raw_app_meta_data` and verifies the resulting trusted claim through the local Supabase CLI.

The script is also available directly:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/set-admin.ps1 -Email user@example.com -Role admin
```

### Hosted Supabase

Use the Supabase Dashboard SQL Editor or a trusted server-side SQL session for the hosted project. Link the project first if using the CLI, then run:

```powershell
npx supabase db query --remote "update auth.users set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{\"role\":\"admin\"}'::jsonb where email = 'user@example.com';"
```

Verify it in the SQL Editor or through the CLI:

```sql
select email, raw_app_meta_data ->> 'role' as role
from auth.users
where email = 'user@example.com';
```

Never add a Supabase service-role or secret key to Next.js environment variables or browser code. The hosted CLI remote operation requires your Supabase account permissions and must be performed outside Next.js.

After either assignment, sign the user out and sign in again. Supabase issues a fresh JWT only after authentication, so an existing session can still contain the previous claim.

## Browser verification

Install the Chromium browser used by Playwright:

```powershell
npm run test:e2e:install
npm run test:e2e
```

The e2e suite starts or reuses the Next.js development server on port 3000. It covers signed-out redirects and a complete registered-student booking lifecycle, including route isolation, rescheduling, completion, incompletion, cancellation, and logout.

Browser tests write results and failure traces under `test-results/`. `npm run test:e2e:install` downloads Playwright's browser into the user-level Playwright cache, outside the project directory.

The local suite can use two persistent accounts:

```dotenv
E2E_ADMIN_EMAIL=test@admin.com
E2E_ADMIN_PASSWORD=Password1.
E2E_STUDENT_EMAIL=test@student.com
E2E_STUDENT_PASSWORD=Password1.
```

Create and assign each account outside registration or browser code:

```powershell
npm run admin:set -- -Email test@student.com -Role student
npm run admin:set -- -Email test@admin.com -Role admin
npm run test:e2e
```

The admin journey is skipped unless both variables are set. Never put these credentials or a Supabase service-role key in browser code or `NEXT_PUBLIC_*` variables.

## Live RLS verification

With local Supabase running and both persistent test accounts created, run:

```powershell
npm run verify:rls
```

The verifier signs in through Supabase Auth and confirms anonymous reads are denied, student ownership is enforced, cross-user inserts are denied, admins can read consultation rows, and admin updates remain denied. It creates one labeled test consultation; the result is intentionally left in the local database for manual inspection.

## Local and generated files

The following are local build, dependency, test, or Supabase CLI state and are not source files:

- `node_modules/` - installed by `npm install`
- `.next/` and `next-env.d.ts` - generated by Next.js development/build commands
- `tsconfig.tsbuildinfo` - generated by TypeScript incremental checking
- `test-results/` - generated by Playwright tests
- `supabase/.temp/`, `supabase/.branches/`, and `supabase/.last-run.json` - local Supabase CLI state
- The Playwright browser cache - stored outside the project by `npm run test:e2e:install`

Do not email `.env.local` or `supabase/.temp/`; they contain local configuration and may include generated credentials. `npm run verify:rls` also creates a test record in the local Supabase database, rather than a project file.

## Verification

- Open `http://localhost:3000/dashboard` while signed out and confirm the `/login` redirect.
- Sign in as a student and confirm booking, list refresh, rescheduling, completion, incompletion, and cancellation behavior.
- Sign in as an administrator and confirm the `/admin/consultations` read-only view.
- Confirm an administrator cannot enter `/dashboard` and a student cannot enter `/admin/consultations`.
